# Мастерская снаряжения — конструктор кастомной формы (Arma 3)

Раздел сайта, где игроки собирают кастомную сборку оружия или комплект
экипировки, крутят модель в 3D и отправляют заказ. Фиксированная цена за
раздел: **оружие — 500 ₽**, **экипировка — 1000 ₽** (админ может изменить
их в панели). Оружие, экипировку и категории/опции к ним админы добавляют,
редактируют и удаляют сами — через `/admin`, без правки кода.

Стек:
- **Фронтенд** — React 19 + TypeScript + Vite, `@react-three/fiber` /
  `@react-three/drei` (Three.js) для 3D, Zustand, Tailwind CSS.
- **Бэкенд** — Node.js + Express + SQLite (`better-sqlite3`), один процесс,
  который отдаёт и сайт, и API, и загруженные `.glb`-файлы. Рассчитан на
  запуск на вашем VPS рядом с tg-ботом (`pm2`/`systemd`), без внешних
  облачных сервисов.

## Быстрый старт (разработка)

```bash
npm install
cp .env.example .env
# в .env впишите ADMIN_USERNAME / ADMIN_PASSWORD — под ними войдёте в /admin
npm run dev        # клиент на :5173 (проксирует /api и /uploads на :4000) + сервер на :4000
```

Откройте `http://localhost:5173` — сайт, `http://localhost:5173/admin` —
панель администратора.

## Прод (на вашем VPS)

```bash
npm install --omit=dev    # либо просто npm install
npm run build              # соберёт клиент (dist/) и сервер (server-dist/)
npm start                   # один процесс на $PORT (по умолчанию 4000),
                             # отдаёт сайт, API и загруженные модели
```

`npm start` читает `.env` (`node --env-file-if-exists=.env`), так что
на сервере достаточно создать `.env` рядом с `package.json` — см.
`.env.example`. Запускайте через `pm2 start npm --name arma3-gear -- start`
или через systemd-юнит, как и сам tg-бот.

При первом запуске, если в базе ещё нет ни одного администратора, сервер
создаёт первого из `ADMIN_USERNAME`/`ADMIN_PASSWORD` (см. `.env.example`).
Дальше новых админов можно добавлять прямо в панели («Администраторы»).

## Структура

```
src/                        — фронтенд (сайт + /admin)
  types.ts                  — общие типы (Weapon, EquipmentSlot, …)
  lib/api.ts                — обёртка над fetch для запросов к API
  store/useBuilderStore.ts  — состояние сборки, грузит каталог с /api/catalog
  pages/PublicSite.tsx       — публичная страница (шапка + вкладки + заказ)
  components/                — 3D-сцена, заглушки, форма заказа и т.д.
  admin/                      — панель администратора (/admin/*)
    AdminApp.tsx              — гейт входа + роутинг
    weapons/, equipment/      — списки и редакторы оружия/экипировки
    AdminOrdersPage.tsx        — лента заказов
    AdminSettingsPage.tsx      — цены разделов
    AdminAccountsPage.tsx      — управление админами

server/src/                 — бэкенд (Express)
  db.ts                     — SQLite-схема + сид стартового каталога
  catalogRepo.ts             — CRUD для оружия/экипировки/цен
  auth.ts                    — bcrypt + JWT-сессия админа (httpOnly cookie)
  upload.ts                   — приём .glb/.gltf (multer), лимит 80 МБ
  routes/                     — публичные и /api/admin/* маршруты
```

## Как подключить настоящие 3D-модели

Пока у оружия/экипировки нет загруженной модели, на сцене рисуется
**процедурная заглушка** (крутится, реагирует на выбор, никогда не ломает
страницу). Как только админ через `/admin` загружает `.glb`/`.gltf` —
он тут же заменяет заглушку у всех посетителей сайта, без деплоя.

- **Оружие** — одна модель на всё оружие целиком (плашка «3D-модель» в
  редакторе оружия). Категории/опции сборки (оптика, насадки…) при этом
  остаются текстовым выбором, который уходит в заказ — они не меняют
  3D-модель. Если нужно показывать разные стволы визуально — заведите их
  как отдельные оружия в каталоге.
- **Экипировка** — модель грузится **на каждую опцию каждого слота**
  отдельно (форма, бронежилет, каска, рюкзак, маска — каждая часть сама
  по себе), и все выбранные части складываются в одну сцену поверх общего
  манекена. У каждой опции в редакторе есть X/Y/Z и «Масштаб» — двигайте
  их, глядя на живой 3D-предпросмотр справа, пока модель не встанет на
  своё место на теле. Слот с `id: "none"` («без каски» и т.п.) по
  соглашению ничего не рисует, даже если туда случайно прикрепить модель.

### Откуда взять .glb модели из Arma 3

Файлы Arma 3 хранятся в проприетарном формате Bohemia Interactive (P3D).
Полный пошаговый пайплайн конвертации — включая **пакетный** импорт целой
папки моделей за один раз и готовый скрипт для пакетного экспорта в
`.glb` — описан в [`tools/README.md`](./tools/README.md)
(инструмент: [`tools/blender_batch_export_glb.py`](./tools/blender_batch_export_glb.py)).
Коротко: Mikero's Tools (распаковать `.pbo`) → P3D Debinarizer → Blender +
аддон **Arma 3 Object Builder** (пакетный импорт `.p3d`) → наш скрипт
(пакетный экспорт в `.glb`) → загрузка через `/admin`. Обратите внимание
на лицензию Bohemia Interactive: экспортировать ассеты из игры для показа
на сайте стоит аккуратно, EULA не всегда разрешает такое распространение
вне игры.

## Оформление заказа и Telegram-уведомления

Кнопка «Оформить заказ» открывает форму (ник, Discord/Steam ID,
комментарий) и отправляет `POST /api/order`. Сервер проверяет данные,
сохраняет заказ в SQLite (виден в `/admin` → «Заказы») и пересылает его
сообщением в Telegram через уже существующего бота модерации.

Переменные окружения (см. `.env.example`, задаются в `.env` на сервере,
**не в коде**):

- `TELEGRAM_BOT_TOKEN` — токен бота из @BotFather
- `TELEGRAM_ADMIN_CHAT_ID` — id чата/группы, куда слать уведомления
- `ADMIN_USERNAME` / `ADMIN_PASSWORD` — первый админ-аккаунт (создаётся
  один раз при пустой таблице админов)
- `JWT_SECRET` — секрет для подписи сессии админа (обязателен в проде)

Если Telegram не настроен, заказ всё равно сохранится в базе и будет
виден в `/admin` — просто не придёт уведомление в чат.

## Интеграция в основной сайт

Этот репозиторий — самостоятельный сервис (фронтенд + бэкенд + база).
Варианты встраивания в основной сайт сервера (когда он появится):

- Развернуть как есть на поддомене/пути (например `armory.вашсайт.рф`
  или `вашсайт.рф/armory` через reverse-proxy) — ссылка с главного сайта.
- Встроить страницу через `<iframe src="https://armory.вашсайт.рф">`.
- Если основной сайт тоже на React — можно скопировать `src/` как модуль
  и переиспользовать API этого бэкенда напрямую (`fetch('/api/catalog')`
  с абсолютным URL вместо относительного).

## Настройка названия сервера

Через `.env` (фронтенд-переменная, попадает в собранный бандл):

```
VITE_SERVER_NAME="Название вашего сервера"
```

## Безопасность

- Токен Telegram-бота и пароли админов нигде не хардкодятся — только в
  `.env`, который не коммитится (`.gitignore`).
- Пароли админов хранятся как bcrypt-хеши, сессия — httpOnly JWT-кука.
- Загрузка моделей ограничена расширениями `.glb`/`.gltf` и 80 МБ.
- Отдельная заметка: в репозитории `tg-moderator` токен бота сейчас лежит
  прямо в `bot.py` открытым текстом — стоит перевыпустить его у
  @BotFather и хранить только в переменных окружения, как сделано здесь.
